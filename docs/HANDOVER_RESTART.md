## 一、产品目标

一个拟人化桌面 AI 伴侣：
- 桌面宠物：可互动的动态立绘，透明小窗，只显示角色，角色以外的区域不拦截鼠标。
- 多家大模型 API 的对话与工作台，Token 用量计量与本机记录。
- 角色：7 个 AI 形象（deepseek、claude、openai、gemini、qwen、kimi、grok），每个角色 4 种形态（少女、萝莉、青年女性、Q 版）。
- 第一批只做一个角色的 4 种形态。角色设定和形象需要重新确定（见第四节）。

## 三、需要重新确定的角色设定（生成人物前必须确定）

在生成任何人物图片之前，先由用户确认以下内容（可以先给出候选，让用户选）：

1. 角色基础：名字、年龄感、性格、说话风格、与用户的关系。
2. 外观设定：发色、发型（长、中、短，双马尾或单马尾等）、瞳色、脸型、体型、肤色。
3. 服装基础款：上衣、下装、鞋袜、配饰。颜色要定成色卡（主色、辅色、点缀色，给出色值）。
4. 标志物：如头顶的呆毛、发饰、耳朵或尾巴等。它们会影响骨骼设计，必须先定。
5. 四种形态的差异：少女、萝莉、青年女性、Q 版。每种形态的身高比例和头身比要写清楚（Q 版头身比约 1:2 到 1:3，其它形态按设定）。
6. 参考风格：插画风格（如日系手绘、柔和厚涂、Q 版糖果色），需要给出参考图或关键词。
7. 版权：只用原创形象，不直接照搬已有的商业角色。

- 正面全身设计图（统一画布，建议 848×1360，即约 1:1.6）。
- 同一角色的色卡与线稿规范（线条粗细、阴影颜色、高光规则）。
- 分层拆件规范（见第七节）。
- 每个部件的单独 PNG（透明背景），每件都要过验收（见第七节）。
- 眼睛、嘴、眉毛的完整拆件，包括闭眼和张嘴的状态图。
- 脸部底板（不带五官），头部与身体的连接区域要补图。
- 头发前后层、侧发、后发，耳朵，尾巴（若有）。

注意：外部 AI 生成的部件总表只作清单参考，不作素材。JPG 没有透明通道，棋盘格是画进去的，设计也可能与设定不一致。

## 五、UI 规格

- 两套风格，都要做，可在配置中切换：
  1. 柔和手绘风。
  2. Q 版糖果风。
- UI 主题可以自定义，所有颜色、字体、圆角、阴影、图片都写在 `config/ui.json`。
- 禁止 emoji：界面、文案、按钮、日志都不允许。图标规则如下：
  - 道具与角色相关图标：PNG 美术图。
  - 界面小图标：SVG 矢量。
- 小窗（桌宠窗口）：透明，只显示角色；角色以外的区域不拦截鼠标；可拖动；可缩放（按同一比例缩放，不用固定像素常数）；可开关鼠标穿透（托盘菜单）。
- 主工作区（Web）：对话区、工作区（API 调用）、资料储存区、Agent 区域（需权限确认）、社交区、链接区（只保存链接，不自动登录、不同步）、生图/生文/生视频/生音频/生代码分区、Token 记录、API 端点配置。
- 布局要不拥挤；窗口缩放自适应。
- 交互光标：小锤子（热点为锤头）、手（热点为指尖）。点击工具按钮后光标变化，立绘有对应反馈。

## 六、软件要求

- 交付形态：Windows 原生 C 桌宠 + Web 主工作区。是否需要 Java 由实现需要决定，不预设。
- 桌宠（C）：透明分层窗、点击穿透、拖动、托盘、右键菜单、缩放、动作状态机（优先级、可中断）、空闲检测（90 秒无输入进入睡眠，任意输入唤醒）、全局输入反应（可选，需用户授权）。
- Web 主工作区：流式对话、API 网关（本机转发，API Key 只在本机保存）、Token 用量记录（每次调用的 token 与费用参考，按功能分类）。
- 数据：聊天、资料、记录、Token 用量全部只存本机。
- 语音：适配层（每个供应商实现统一接口：STT、TTS、实时双向语音）。切换供应商时在配置中切换，不写死一家。语音通话支持打断（barge-in）与接话（端点检测）。
- 实时配音：回复语音与文字同步；口型跟随音频（AEIOU 或音素）。
- 社交（每项独立开关，默认全部关闭，每项可设 token 上限）：
  - 群聊：用户与多角色群聊，达到 token 上限即停。
  - 循环回答模式：角色按顺序回应（群聊关闭时）。
  - 朋友圈：角色定时或手动发布动态，可设发布频率与 token 上限。
  - 双角色同时召唤聊天：两角色之间对话。
  - 请求打电话：角色主动请求语音通话（需用户同意）。
- 生图、生文、生视频、生音频、生代码：分区展示，各自适配，具体供应商待定。
- API 接口：官方接口与 OpenAI 兼容本地接口，每角色可独立配置。OpenAI 直连默认关闭，需用户手动开启。测试阶段只用中转站，模型用实惠的 Gemini、DeepSeek。
- 中转站选型标准：OpenAI 兼容接口；明确标注模型来源；支持 Gemini 与 DeepSeek；有按量计费明细与余额查询；有明确的退款与失败计费规则。候选（平台自述，未经本项目实测）：zenmux.ai、crun.ai、easyrouter.io。
- 测试与验收：
  - `scripts/selfcheck_all.sh` 全绿。
  - 每次交付必须标注测试标签：[测试锁]（单元测试与构建）、[沙箱实测]（沙箱内可验证的部分）、[需真机]（窗口透明、穿透、光标、动画观感、音频、Windows 持久化）。
  - 不替用户宣布真机项完成。

## 七、自定义（配置文件，不改代码即可扩展）

目录：`config/`，文件如下：
- `ui.json`：主题、图片路径、布局、两套风格的切换。
- `characters.json`：角色与形态（名称、形态列表、每种形态对应的拆件清单、默认服装、默认音色）。
- `outfits.json`：服装（每套服装的部件清单、适用形态、切换方式）。
- `accessories.json`：配饰（猫耳、猫尾或其它；挂载点、z 序、是否随形态切换在配置中声明；可继续添加）。
- `features.json`：功能开关（社交、语音、朋友圈等，默认全部关闭；每项 token 上限）。
- `providers.json`（建议新增）：API 供应商与中转站（base_url、模型名、启用开关）。
- `voices.json`（建议新增）：角色音色映射（按供应商分别配置；音色绑定到角色，形态切换不换音色；形态可选覆盖）。

目标：新增角色、道具、话题、配饰、主题，只需要改配置和增加素材，不改代码。

## 八、怎么制作动态立绘（完整流程）

### 8.1 方法
- 方法 A（已确定）：AI 生成部件 PNG，代码实现 2D 骨骼与网格形变（Web 端 canvas 或 WebGL），不依赖 Live2D 编辑器。
- 眨眼参数、视线裁剪、呼吸分段等，参照 Live2D 的做法实现（见第二节）。

### 8.2 拆件（每个形态都要做）
按下列层级拆，每个会动的部位独立成层，层序从前到后：
1. 前景饰品：呆毛、发饰、眼镜或帽子（若有）。
2. 前发：中、左、右；鬓角。
3. 眉毛 L/R。
4. 眼睛 L/R：上眼睑、下眼睑（与脸同色的遮挡层）、上睫毛、下睫毛、双眼皮线、眼白（作剪贴遮罩）、虹膜、瞳孔、高光（在虹膜上方）。
5. 嘴：上唇线、下唇线、上牙、下牙、舌、口腔底色（比嘴线大一圈）。
6. 脸底色（补全脸型，不含五官）、腮红、鼻子与鼻影、耳朵 L/R（向内画长，埋进头发）。
7. 脖子（向上插进头，向下插进胸口）。
8. 上半身：内衬、外套前片 L/R、外套后片、领结或领子、胸部（若有）。
9. 下半身：裙子或裤子前后片；上下半身交界处有“弯腰重叠区”，补图。
10. 手臂 L/R：大臂、小臂、手掌；肩、肘、腕补图。需要抓取时手指单独拆。
11. 腿 L/R：大腿（根部补图）、小腿、袜子、鞋。膝、踝补图。
12. 后发（脑后，补图到发根）。
13. 尾巴（若有，分段，每段关节补图）。
14. 后景与道具：后背装饰、披风后片、手持道具、地面阴影。

拆件规则（来自用户与教程）：
- 所有会动的部位独立成层；对称部件（左右）不合并。
- 被遮挡的部位要补全（刘海下的眉与额头、关节两侧都要画完整），否则转动时会裂缝。
- 图层命名英文，按层级建组（如 Head -> Eye_L -> Pupil_L）。
- 阴影可单独成层（正片叠底），让转头时产生位移。

### 8.3 生成与验收（每个部件都要过）
- 尺寸：统一画布（如 848×1360），透明背景，无白底残留。
- 颜色：与设定色卡一致，取样比对。
- 形状：与设计图的轮廓重合度达到阈值（用蒙版比对），不能只看颜色。
- 位置：与底板的关节对齐（肩、肘、髋、膝、踝、颈、头）。
- 不通过：自动重试，最多三次；三次仍不通过则记录原因，不入库，不标记为完成。
- 用 AI 生成部件时，应以设计图为参考输入，并要求同时保持颜色和线条。生成后必须用蒙版与颜色取样检查，不能直接入库。

### 8.4 骨骼与形变
- 骨骼层级（父子）：
  - ROOT（世界坐标）
  - 下半身（双腿与脚锁定地面，裙摆绑定腿部）
  - 上半身核心（呼吸组：胸部与内衬做 Y 轴缓动）
    - 双臂（肩、肘、腕；需要时做 IK）
    - 颈与头总控
      - 后发物理组
      - 头部形变区（脸底、耳朵、五官、前发）
      - 头部前置特效（呆毛、光环、发饰）
  - 尾巴（若有）：根部、中段、尾梢，多段钟摆物理。
- 关节补图：肩、肘、腕、髋、膝、踝、颈的交界两侧都要补图。
- 网格形变：脸、身体的大块区域用网格（mesh），在关节处做平滑形变。

### 8.5 眼睛
- 标准分层：上下眼睑（同脸色遮挡）、睫毛、眼白（剪贴遮罩）、虹膜（裁剪到眼白内）、高光（在虹膜上方，可用双层遮罩）。
- 视线跟随：虹膜按鼠标方向移动，并裁剪到眼白内；眼白要画出被遮住的部分。
- 眨眼：按 Live2D 状态机（闭合 0.1 秒、闭着 0.05 秒、睁开 0.15 秒、间隔随机）。眼皮图层从上方下落，盖住虹膜。
- 不要用羽化椭圆或程序画的近似眼皮（已验证边缘有色差）。

### 8.6 动作与状态
- 状态机（优先级、可中断、过期）：待机、专注（跟随鼠标）、喜悦、低落、说话、摸头、摸脸、锤击、抚摸、点击身体、睡眠、思考。
- 参数映射：
  - 待机：瞳孔微动，随机眨眼，胸腔 Y 轴正弦缓动，呆毛微风。
  - 专注：眼球追踪光标，头部 Z 轴微侧，上半身微前倾。
  - 喜悦：眉毛上扬，高光放大，嘴角上扬，身体轻跳，尾巴高频摆动。
  - 低落：眉毛下压，上眼睑下压（半闭），脖子前倾，肩部内收，尾巴自然下垂。
  - 说话：按音频音素切换口型（AEIOU），肢体小幅随机晃动。
- 摸头：指针在头部顶部 30% 区域，眯眼，小跳。
- 摸脸：脸红，手出现，表情变化。
- 锤击：光标为锤子，落锤点有震动和锤子动画。
- 睡眠：空闲 90 秒后闭眼，摆动减慢，任意输入唤醒。

### 8.7 测试
- 预览：本地用 Vite 开发服务，地址为 `http://localhost:5173/<页面路径>`。
- 对外预览只通过 Arena 界面的预览面板打开，不给外部拼接的域名链接。
- 每次改动后，检查：图层是否对齐、眨眼是否干净、关节是否裂缝、身体是否分段动（腰以上动，腰以下静止）。
- 语法检查：`node --check` 检查脚本。
- 真机验证（窗口透明、穿透、光标、Windows 持久化）标注 [需真机]，由用户确认。
