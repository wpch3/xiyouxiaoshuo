# AI 桌宠产品计划

按阶段推进；先把现有数据与代码测试通过，再进入下一阶段。测试失败时先修当前阶段，不跳着扩功能。

## 阶段一：现有功能验证

- 官方与 OpenAI-compatible API：聊天、错误显示、真实/估算用量。
- 本机资料库：文本提取、本机保存、勾选资料进入请求上下文。
- 角色群聊：按角色顺序回应、API 失败处理、用量记录、超时退出。
- 桌面 Agent：用户选择工作目录后读取文件；写入和命令执行逐次确认并限制在所选目录。
- 本机保存：API 配置与 Key、聊天/用量记录、资料库在关闭重启后仍可用。
- 语音输入及目标语音模式的接口支持验证。

## 阶段二：实时语音通话模式

- 目标是类似 GPT 电话模式的双向实时语音：麦克风输入、语音回复与文字转录同步、支持打断和接话。
- 独立 TTS 播报按钮不作为目标功能；已从界面和网关移除。
- 必须先确认所选供应商支持实时音频接口（如 WebRTC/WebSocket 双向音频）、模型和鉴权方式；仅有 Chat Completions 或批量 TTS 不等于支持实时通话。
- 用户当前使用 OhMyGPT；未经确认，不自动改用更贵的其他供应商。

## 阶段三：数据驱动的工作区

工作区应可按项目类型分区，并允许各区使用自己的提示词、上下文资料、模型/API 配置和用量记录：

- 图像生成
- 视频生成
- 音乐生成
- 代码生成
- 综合工作

## 阶段四：可自定义角色与 UI 数据

- 七个现有角色各支持萝莉、少女、青年、Q 版四种形态和多套服装。
- 角色、主题和布局数据与 React 组件逻辑分离，便于替换立绘、分层素材、骨骼/动画、颜色、字体、布局和角色对话。
- 先完成 DeepSeek 少女骨骼样板，确定统一素材/骨骼清单格式，再逐步扩展角色。
- 配置包需支持版本校验、导入/导出、预览、恢复默认与缺失素材回退。

## 贯穿范围

- 保留桌宠互动：抚摸、摸脸、点击、道具/锤子、零食和对话反馈。
- 聊天、资料和记录默认本机保存；用户明确勾选的资料才随请求发送给所选 API。
- GitHub/云盘链接区目前是快捷链接；实际云端登录/同步需另行确认，不默认上传。
