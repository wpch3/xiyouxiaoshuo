# 桌宠产品实施路线图

## 用户明确的产品要求
- 先把桌宠本体做好：高清动态立绘、可爱且清晰的 UI、可实际操作的互动。
- 交互道具必须是鼠标工具：点选小锤子后，鼠标移到角色上显示锤子图像，点击角色触发击打动画；抚摸工具支持按住并拖动，角色跟随产生反馈。
- 不使用 Emoji 作为图标、道具、食物或情绪表达；使用高清角色图片、可缩放矢量插画和图片素材。
- 角色反应由动作驱动；不以预设台词冒充 AI 对话。聊天气泡只显示真实 API 对话或明确的运行状态。
- 保留现有 7 个角色、每个角色 4 种形态；计划统一重绘分层立绘素材，服装设计由助手完成。
- 之后继续完整规划：API/用量、本机资料库、Agent、角色群聊、社交互动、链接区、自定义 UI/角色素材、分类型工作区（图像、视频、音乐、代码、综合），按阶段验证，不跳过失败项。

## 当前正在实施：桌宠动态立绘与鼠标互动
1. 使用高清主立绘作为首个样板，并搭建跨角色的动态舞台组件。
2. 实装待机呼吸、鼠标视线追踪、抚摸拖动反馈、小锤子图像光标与点击反馈。
3. 调整桌宠主面板为柔和、圆润、可爱风格；全应用清除 Emoji UI 字符。
4. 为 7 个角色各 4 种形态建立素材检查清单；样板确认后分批重绘，不能把现有低质素材当作最终交付。

## 后续阶段
- 完成 7 角色 × 4 形态的高清图像资产；分层素材需保证角色身份、服装和相对尺寸一致，再添加更精细的眼睛、头发、手臂和服装摆动。
- 逐个复测已有聊天/用量、资料库、Agent、角色群聊、链接区、桌面持久化；真实供应商测试与模拟测试分开汇报。
- 真正的实时语音模式须使用已确认支持双向实时音频的服务，包含文字同步与可打断；不恢复独立 TTS。
- 工作区按图像生成、视频生成、音乐生成、代码生成、综合工作分类；每区单独配置模型/API、提示词、资料上下文和用量记录。
- 角色、形态、服装、颜色、互动命中区和 UI 皮肤最终数据驱动，允许用户定制并在本机保存。

## 验收原则
- 视觉验收：预览中实际检查透明背景、边缘、清晰度、比例和缩放，不只检查文件存在。
- 互动验收：点击工具按钮后光标真实改变；拖动抚摸和点击锤击均在角色区域触发真实动画，不显示 Emoji 道具，不生成预设聊天台词。
- 功能验收：每一步记录已实现、自动测试、真实 API 测试和桌面实机测试的区别；未测过的内容不得标为完成。

## 分层拆件实施（Live2D/Spine 规范的 Web 等价物）
- 拆件原则采纳：头发分前发/侧发/后发、眼睛左右独立且含睫毛/眼白/瞳孔/高光、嘴含口腔/舌、脸底/腮红/耳、脖子补图、衣服与肉体分离、四肢左右独立；被遮挡关节必须补图；对称部件不合并；图层英文命名并建组。
- 本管线不使用 Live2D/Spine：部件为同尺寸透明 PNG + `app/src/constants/petRig.js` 清单（z 序与动画映射）+ `LayeredPetRig` 组件叠放渲染。
- 已实装：小寻少女形态八层（base_final 补图底、mouth_open 口型、iris 视线、eyelids 眼睑、brows 情绪眉、side_hair_l/r 反相摆动、bangs 刘海摆动），眨眼/口型/视线/眉毛均有组件测试（9/9）。
- 待做：小寻其余三形态与其余 6 角色的拆件集；后发分段物理摆动、手臂挥手/抓取层（大臂/小臂/手掌）、口腔内部细分层（牙/舌）。
