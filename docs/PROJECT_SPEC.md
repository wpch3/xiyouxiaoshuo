## 1. 产品定位

拟人化桌面 AI 伴侣：桌面宠物（可互动的动态立绘）+ 多家大模型 API 的对话与工作台 + Token 用量计量与本机记录。
角色为 7 个 AI 形象（deepseek、claude、openai、gemini、qwen、kimi、grok），每个角色 4 种形态。

## 2. 用户硬性要求（逐条归纳，来自历次对话）

### 2.1 桌宠本体（最高优先级）
1. 动态立绘：可动，分层拆件 + 骨骼/网格动画（Live2D/Spine 式），不是整张图的抖动。
2. 四种形态切换：少女、萝莉、青年女性、Q 版。切换要有效、要平滑。
3. 服装功能：每个角色多套服装，换装真正改变立绘（当前不成立，见第 3 节）。
4. 互动：
   - 小锤子：点击桌宠按钮后，鼠标光标变成小锤子，在立绘上点击有敲击反馈；
   - 手抚摸：点击按钮后，光标变成手，按住拖动有抚摸反馈；
   - 摸脸 / 摸头 / 点击身体：不同区域不同反应；
   - 以上为真实交互（光标变化 + 立绘反馈），不是预制对话。
5. 对话互动：与角色的对话影响表情与动作。
6. 小窗口（桌面小窗）：透明，只显示角色；角色之外的区域不可点击（不拦截鼠标）。
7. 图片尺寸：立绘、拆件、小窗尺寸统一规格（见第 5.4 节，目前不统一）。
8. 可爱风格：UI 要可爱、好看。
9. 道具：鼠标点击道具按钮 -> 光标变道具（小锤子、手），不是 emoji，不是对话预制。
10. 小零食、小道具：要做（功能可以后加，但形态要预留）。

### 2.2 全局约束
- **禁止 emoji**，任何界面、文案、按钮、日志都不允许。所有图标必须是高清图片（PNG/SVG 矢量）。（当前仓库已扫描：0 处 emoji，见第 3 节。）
- 不乱改用户的程序想法；功能可以分期，但规划不能丢。
- 每次交付：完整实施 + 汇报 + 真实测试清单（[测试锁] / [沙箱实测] / [需真机]），不替用户宣布真机项完成。
- 素材不符合要求时自行生成、修改、优化，不把问题推给用户。

| --- | --- |

## 5. 桌宠动态立绘规格（待确认后执行）

### 5.1 拆件原则（用户给出的 Live2D/Spine 标准）
- 头发：前发（可分左中右）、左右侧发分开、后发在最底层、呆毛/马尾分段。
- 眼睛：左右眼独立建组；每只眼内拆：眉毛、上睫毛、下睫毛、眼角睫毛、双眼皮褶线、眼白（遮罩用）、虹膜/瞳孔、高光（独立，保持受光面）。
- 嘴：上唇线、下唇线、口腔底色、上牙、下牙、舌头。
- 头与脸：脸底（肤色底板）、左耳、右耳（耳饰单独）、鼻子（阴影高光合并）、腮红。
- 身体：脖子（上伸进头后、下伸进衣内）、上半身、下半身（需弯腰时拆开）、衣物（领结、披风、飘带、前裙摆、后裙摆分层）。
- 四肢：左右手、左右脚全部分开；大臂、小臂、手掌；需要抓取时手指单独拆；大腿、小腿、鞋子。
- 补图原则：被遮挡部位全部补全（刘海下的眉与额头、关节交界两侧都要画完整圆形），否则转动时出现裂缝。
- 对称部件不合并（Arm_L 与 Arm_R 独立）。
- 图层命名：英文，按层级建组（如 Head -> Eye_L -> Pupil_L）。

### 5.2 实施方式（待用户确认，见第 10 节）
- 方案 A（推荐）：用 AI 生成各拆件 PNG，用代码实现 2D 骨骼 + 网格形变（Web 端 canvas/WebGL），无需 Live2D 软件。
- 方案 B：导出 PSD，由用户在 Live2D Cubism 中手动绑定。
- 方案 C：Spine。

### 5.3 动作清单（待定，建议）
待机呼吸、眨眼、视线跟随、口型（AEIOU 与 语音同步）、摸头（眯眼+点头）、摸脸（脸红+手）、小锤子（被敲后的晃动与惊讶）、抚摸手（脸红+笑）、点击身体（跳/缩）、睡眠（闭眼+摆动减慢）、拿零食（张嘴）、思考（歪头）、换装（短暂消失再出现）。

### 5.4 图片尺寸统一（建议）
- 统一立绘画布比例：建议 1:1.6（如 800×1280 或 848×1360），全角色、全形态一致。
- 拆件与立绘共用同一画布与锚点（脚底中心），便于叠放。
- 小窗按同一比例缩放，不再用固定像素常数。

## 9. 规划中缺失或需要补充的功能（建议，待用户取舍）

以下是我认为一个 AI 桌宠应有、但用户列表中未出现的内容。均为建议，不擅自实现：

1. **长期记忆与人设**：角色记住用户的偏好、近况（本机存储，可查看、可清空）。
2. **好感度与羁绊**：已有好感度数值，需要定义如何增长、影响什么（表情、台词、解锁服装）。
3. **作息与提醒**：喝水、休息、番茄钟提醒，系统通知。
4. **数据导出与备份**：聊天、资料、Token 记录可导出/导入（JSON），防止换机丢数据。
5. **隐私控制**：一键清除本机数据；API Key 加密存储（Windows DPAPI 或等效方案）。
6. **Agent 安全**：权限分级（读/写/执行）、操作审计日志、单次确认。
7. **桌宠系统集成**：开机自启、多显示器、DPI 缩放、窗口位置记忆。
8. **性能预算**：桌宠常驻时 CPU 占用、内存上限、帧率目标（建议 30 fps，待真机测）。
9. **素材授权与来源记录**：每张 AI 生成图的生成工具与提示词留档，便于追溯与替换。
10. **无障碍**：键盘可操作、字号可调、对比度达标。
11. **更新机制**：版本号、更新提示（先不做，记录在规划）。
12. **测试与验收**：真机测试清单（Windows 10/11，单显示器与双显示器）。

## 10. 需要你确认的问题

### 10.1 产品与美术（优先）
1. **动态立绘方案**：用 AI 生成拆件 + 代码骨骼形变（A，推荐），还是导出 PSD 你自己用 Live2D 绑定（B），还是 Spine（C）？

4. **可爱风格**：偏向哪种？（如 Q 版糖果色、柔和像素、日系手绘、或保留现有插画风格只改 UI 外观）
5. **图片尺寸**：是否同意统一画布比例（如 1:1.6）？

### 10.2 功能
6. **社交**："角色社交"指什么？（角色之间互相聊天、用户与多角色群聊、角色动态/朋友圈、还是别的？）
7. **生图/生视频/生音频/生代码**：是调用各家 API，还是本地模型？每个分区需要哪些具体功能？
8. **小道具/小零食**：是否有经济规则（用 Token 或好感度购买）？还是免费互动？道具图标用 AI 生成的图片还是素材库？
9. **话题制造选项**：由模型实时生成，还是预设池随机抽取？
10. **语音供应商**：语音通话与实时配音用哪家（OpenAI Realtime、其它）？是否允许按量付费？是否需要角色专属音色？

11. **交付形态**：最终是 Windows 桌面应用（C 原生桌宠 + Web 主工作区），还是纯 Web？之前提到过 Java，是否仍需要 Java 部分？

14. **已删除的参考仓库**：VPet、airi 因体积太大已删除，需要时我会用稀疏检出只拉取相关目录，是否可以？
